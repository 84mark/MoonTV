# 共享视频源与测速

## 数据来自哪里

豆瓣提供电影、剧集和综艺的推荐目录及海报。实际搜索结果、剧集地址和播放链接
来自 `config.json` 中的 MacCMS 采集 API，MoonTV 本身不维护影片数据库。

登录后从用户菜单进入「视频源管理」（`/sources`），可以查看名称、接口地址、
内置/自定义来源，新增、编辑、停用或删除源，导入导出 JSON，读取 GitHub 源列表。
所有修改先进入草稿，点击「保存到所有设备」才写入 D1。
并发保存使用配置版本检查，另一设备已修改时返回冲突，不覆盖你的草稿。

共享配置一旦存在，完整替代内置源列表，不会在冷启动或重新部署时把已删除的源补回来。
新的搜索、详情、播放记录续播及资源列表接口均使用它；这些响应不进入共享 HTTP 缓存。
恢复内置列表也先进入草稿，需要明确保存。

当前 `localstorage` 登录模式仍保持不变：播放记录、收藏属于各自浏览器。
所有持有本站共享密码的人都可以管理共享源。若启用已有的多账号存储模式，
则仅站长和管理员可以修改。此次接入不切换登录方式或迁移旧收藏。

## Cloudflare D1 配置

1. 在 Cloudflare「Storage & databases → D1 SQL Database」创建独立数据库，
   建议名称 `moontv-sources`。
2. 在该数据库 Console 执行 [迁移 SQL](../migrations/sources/0001_source_settings.sql)。
   它只创建 `moontv_source_settings` 表，不删除或修改其他表。
3. 在 Pages 项目 `moontv` 的「Settings → Bindings」添加 D1 Database 绑定：
   变量名 **`SOURCE_DB`**，选择刚创建的数据库。生产环境必须配置；
   若需要预览环境也可单独绑定，预览数据库建议与生产隔离。
4. 重新部署最新提交，打开「视频源管理」，确认没有“尚未绑定”提示并保存一次。
5. 在另一浏览器或设备登录，确认能看到同样配置。

**不要修改 `NEXT_PUBLIC_STORAGE_TYPE`，也不需要为此添加 `USERNAME` 或更改 `PASSWORD`。**
`CLOUDFLARE_API_TOKEN` 是管理 Cloudflare 时使用的部署凭据，不属于 MoonTV 的运行配置，
不应存放在 Pages 项目的环境变量中或提交到仓库。

未绑定 `SOURCE_DB` 时应用仍使用原有内置源，不支持假装已共享保存。
绑定后必须先执行迁移；数据库错误会明确报告，不能悄悄写入内存当作持久化成功。

## GitHub 更新与接口检测

管理页提供以下第三方订阅的入口：

- https://github.com/dxs1256/MoonTV-api ：定时检测报告、健康版 JSON。
- https://github.com/shijianus/moontv-source ：分类影视源列表。

支持本站导出的 `{ "sources": [...] }` 和 MoonTV 的 `{ "api_site": {...} }` JSON。
导入时先预览，再合并或替换草稿；合并优先匹配稳定 ID 或相同 API，保留现有 ID
及停用开关。不会静默下载、执行脚本或定时替换源。第三方 `detail` 往往只代表主页，
不会给普通 JSON 源错误启用旧式 HTML 详情抓取。

接口检测通过 Cloudflare 服务器发出 GET 并校验 JSON 的 `list` 字段，
区分 HTTP 错误、防护页、空列表、超时和网络受限，显示的是**接口响应耗时**。
最多同时检测三个接口，可以停止；失败不会自动删除或停用源。
内置源核验记录见 [本次检测报告](source-audit-2026-10-22.md)。

## 播放页测速

旧逻辑只给四秒超时、用独立 HEAD 请求计时，且必须同时取得分辨率和速度才结束，
导致慢启动、原生 HLS、HEAD 被拒绝或速度不可观测时出现误判。

新逻辑使用当前浏览器的原生 HLS 或 hls.js，检查真实播放列表、分片与媒体事件：

- 分别显示「播放已确认」「接口可达」「预检未确认」；缺少速度不是不可播放。
- hls.js 使用真实 GET 的响应/分片统计，不再发送 HEAD 或用 opaque 响应伪造测速。
- 原生 HLS 可以确认播放，但浏览器通常不提供分片字节数，明确显示「未测得」。
- 预检最长十二秒，自动优选先测前三个候选、最长八秒；没有确认结果则保留原有顺序。
- 同时最多三路媒体预检，重复 URL 合并，短期缓存；可手动重新检测。
- 优先使用首集采样，不再误取第二集；清理播放器、计时器和网络加载资源。
- 当前播放器的 `canplay` 事件会更新「播放已确认」，优先于先前的失败或未知预检。
- 搜索解析保留 `.m3u8` 后的鉴权参数，API 地址已有的查询参数也会保留。

这些是短时采样，不能保证整部影片、每集或所有网络环境的持续播放速度。

### 2026-10-22：按实测速度选择与筛选

开启“优选和测速”时，自动优选将所有候选交给并发上限为 3 的检测队列，不再只检查前三个，也不等待整批结束。首个返回正速度的结果立即进入播放，其余检测继续完成。播放开始后不因其他源更快而自动切换，用户仍可选集和手动换源。

换源列表按速度降序排列（统一换算 KB/s、MB/s），当前源不强制置顶。所有候选完成前保留未测得速度的行；全部完成后隐藏无正速度的行。全部无速度则停止播放器，显示“当前所有源均不可用”和重新检测入口。该提示按“是否测得速度”判定，浏览器无法取得速度的源也会隐藏；不删除共享数据库里的源。关闭测速时仍保留手动播放列表。

### 详情页提前测速与播放交接

进入详情页即在后台搜索匹配片源并测速，不启动播放器。检测未结束时保留首个测得正速度的片源；全部完成后改选速度最快者。点击播放时将这组候选和已有结果交给播放页，使用已选片源，不重复搜索或重复测速。尚未得到结果时仍允许立即进入原播放流程。

若全部完成且没有测得正速度的片源，播放按钮置灰，提供“重新检测”；重试重新搜索并强制采样，跳过旧测速缓存。网络搜索失败不等同于全部片源失败，此时保留正常播放入口。预检测交接只保存在当前浏览器内存，最多 8 组、有效期 5 分钟；刷新或打开新标签造成缓存缺失时，自动退回原播放流程。选集和手动换源保持不变。
